# Day 2 plan (2026-10-22): Telegram channel + scan/replies CLI

Goal: the agent reaches the user where they chat. Telegram is the first
channel - alerts, handoff links, and approve/skip replies - behind a
pluggable channel interface so contributors can add WhatsApp or others.
Also wire the `scan` and `replies` CLI subcommands listed as day-1 gaps,
and put the test suite in CI.

Steps:

1. `jobhunter/channels/` package: `Channel` interface (`send_alert`,
   `poll_decisions`), `Decision` type.
2. Telegram channel on the official Bot HTTP API. Token and chat id from
   the environment only. Pure request builders + injectable transport so
   tests stay offline.
3. `FakeChannel` for tests and dry runs.
4. `channels/ops.py`: adapt a channel to the pipeline notifier; apply
   approve/skip decisions to the LinkedIn queue and the tracker.
5. Config: `rss_feeds`, `agent_reach_queries`, `channel_state_path`.
6. CLI: `scan`, `replies`, `channel poll`.
7. Tests: telegram unit tests, ops tests, CLI integration tests.
8. CI: GitHub Actions running the unittest suite on 3.10-3.12.
9. CODEOWNERS so review routes to the owner; docs updates.

Constraints (unchanged): tests offline, no secrets in the repo, no
auto-applying, nothing sends LinkedIn messages, the channel never acts
on its own - it notifies and carries the human's decisions back.
